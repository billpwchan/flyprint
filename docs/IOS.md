# 航迹 iOS

## 定位

Flighty 的中心是下一班飞机：实时状态、晚点预测、登机口、前序航班。它的历史部分（Passport）是附带的：免费只导入 365 天，不收表格，按航班号一条条加。航旅纵横和飞常准把历史行程和足迹放进会员。

航迹的中心是一个人全部的飞行：住过哪里，从家出发去了哪些地方，和谁一起飞。下一班也放在这条线上看：第几次飞这条航线，第一次去这个国家，下次和谁在哪里见面。

## 比 Flighty 强在哪里

| | 航迹 | Flighty（2026-11，v4.12） |
|---|---|---|
| 带入历史 | 任意格式一次带齐：截图、行程单、PDF、各家 App 导出、表格；重复上传不会重复记 | 免费 365 天；不收自定义表格；手动只能输航班号 |
| 读懂旅程 | 按"夜晚在哪里过"推断各时期的家，航班自动成行程：往返、搬家、中转、停留 | 只有航班列表与统计 |
| 地图 | 照片式的地球，白天是卫星照片，夜里是城市灯光，晨昏线在真实位置；一班一条弧线，同一航线按次数和方向展开成扇面，光点沿飞行方向走；打开一班飞机，太阳转到它起飞那一刻 | 照片式地球；历史航线热力图 |
| 天气 | 每一班起飞、落地那一小时的天气，每次停留每一天的天气，多年前的和两周内的都有，画成舷窗里的天 | 接下来航班的目的地天气 |
| 两个人 | 各自的账户、各自的航线；联动后有一个只属于两人的同飞页和"下次见面" | Friends 共享实时航班 |
| 中文与亚洲 | 简体、繁体、英文；1141 家航司名称，988 个航司标志 | 英文为主，非美国数据弱 |
| 账户 | 网页与 App 同一账户，随时导出 | 绑定一个 Apple ID，无网页版 |

当天出行这一面，第一版用航班计划时刻做到 Flighty 的形态：倒计时、Live Activity 和灵动岛（起飞前的倒计时，空中进度，落地当地时间）、小组件。实时状态需要数据源，放在第二阶段。

## 和同类 App 比还缺什么（2026-11-20 盘点）

对照 Flighty、航旅纵横、飞常准和几款飞行日志（App in the Air 停服后的 Flightera、Air Travel Log、JetLovers）。按「没有它，用户会觉得这个 App 不完整」排：

| 功能 | 别人怎么做 | 航迹 | 状态 |
|---|---|---|---|
| 一段一段手动添加、修改、删除 | Flighty 按航班号加，左滑删除；日志类 App 每段都能改座位、舱位、注册号、备注 | App 和网页都能添加、修改、删除；机场输入代码、城市或机场名都行，边打边给候选（伦敦、Heathrow、希思罗、LHR），名字只对应一个机场时，离开输入框就换成它的代码，保存前看得到；多机场城市和几国同名的城市不替人猜，从候选里选 | 已做 |
| 扫登机牌 | Air Travel Log、App in the Air 扫条码；航旅纵横自动同步 | 相机扫，或从截图里读条码（IATA BCBP）：航班号、日期、航线、舱位、座位；条码没有年份时提醒核对日期 | 已做 |
| 出发前提醒 | Flighty 值机提醒、出发提醒；航旅纵横值机提醒 | 本机通知：起飞前 24 小时提醒值机，国际 3 小时、国内 2 小时前提醒出发；按日程计算，不含实时变化 | 已做 |
| 加到日历 | Flighty 自动同步日历 | 未来航班一键加到系统日历（不需要日历权限） | 已做 |
| 实时状态、晚点、登机口、前序航班 | Flighty 和飞常准的核心 | 没有 | 需要数据源，见第三段 |
| 推送、Live Activity、小组件 | Flighty | 没有 | 小组件和 Live Activity 需要 App Group 和扩展，免费开发者账号不能签；推送需要 Developer Program |
| 邮件转发自动导入 | Flighty、TripIt：把订票邮件转到一个地址 | 网页和 App 可以上传 .eml、粘贴邮件正文 | 需要收信基础设施（域名 MX、收件服务），待定 |
| 年度报告、分享卡片 | 航旅纵横年度报告；Flighty Passport | 一年（或全部年份）、一次旅程、一段航班各一张 3:4 的卡，App 与网页同一套设计 | 已做 |
| 分区导航 | Flighty 底部分成几个模块（航班、Passport、朋友） | 底部三个分区：旅程、航班、足迹，搜索是旁边单独的圆钮 | 已做 |
| 天气 | Flighty 给接下来航班的目的地天气 | 起飞、落地那一小时和每次停留每天的天气，过去和未来两周都有 | 已做 |
| 日历导入 | Flighty 读日历里的航班 | 导入收 .ics 文件 | 读系统日历需要完整日历权限，暂不做 |

## 用户的几个时刻

1. **第一次打开**：全屏的欢迎页压在一位虚构旅客（Lin）九年的地球上，三屏左右翻：全部航线；其中一次旅程（地球飞到那趟旅程）；三班航班怎么被导入。右上角就能切简 / 繁 / EN。三个出口：创建账户、我有账户、先看看示例；看示例时右上角的人像随时回到注册。
2. **带入历史**：注册后直接选截图和文件，或从别的 App 分享进来。读完以后，地球按年份把这个人的航线一条条画出来。这是第一个惊喜，没有进度日志。
3. **平常打开**：地球和当年的航线。底部卡片只放此刻相关的一件事：有行程就是下一程倒计时，没有就是最近一次旅程。
4. **出发前**：下一程卡片写清去哪、第几次、谁也在这班。航班页一键加到日历；打开行前提醒后，起飞前 24 小时提醒值机，2 到 3 小时前提醒出发。起飞前 3 小时自动开始 Live Activity（第二段）。
5. **在天上**：灵动岛显示进度和落地当地时间；地球上一个光点沿弧线走；日出在哪一侧窗外。
6. **落地**：一条安静的通知，例如"第 63 次飞行，第一次到葡萄牙"。新弧线融进地球。
7. **回看**：旅程、城市、年份、同飞。

## 设计

**一句话**：夜色地球上的光。航线是光，界面是落在地球上的深色玻璃；每个对象以自己的样子出现，文字只做标注。

第一版的问题是文字一行行堆着，用的是系统默认的灰色卡片、带圈的玻璃按钮和"标签：值"的行，和 Flighty 不在一个水平。Flighty 好在三件事：信息按机场显示屏的优先级排；颜色和图标先于文字表达状态；每样东西都以实物出现（地球、涂装的机型、护照、翻牌数字）。航迹的长处在历史和旅程，所以这一版让每个对象都"被看见"：

| 对象 | 以什么样子出现 | 素材来源 |
|---|---|---|
| 首页 | 底部三个分区：旅程（下一程和按年的旅程）、航班（接下来的在前，飞过的按月倒序，每行一条那一程的天色）、足迹（数字、去过的国家和城市）；年份尺在三者之间共用，换分区不丢年份 | 自己的数据 |
| 一个人的飞行 | 照片式地球上的光弧，同一航线按次数展开 | 自己的数据；NASA Blue Marble 与 Black Marble |
| 天气 | 一扇舷窗：窗里的天按那一刻的太阳高度变色，云多了天变灰，雨、雪、雾、雷画在窗外；航班页两端各一扇（起飞、落地那一小时），停留每天一扇，下面写最高、最低温 | Open-Meteo（经服务器） |
| 年份 | 年份尺（「全部」之后从最近一年往前排，最近的一转就到）；这一年的月份条（每班一个点）；这一年第一次去的地方 | 自己的数据 |
| 旅程 | 目的地的卫星影像；行程是一条时间线，每段航班下面是那一程的天色，停留是夜晚的点 | Apple 地图影像 |
| 航班 | 机场显示屏式的大字；两地之间的连线就是沿途天色（日出日落、在哪一侧窗外）；机型的实测侧视图或这架飞机的照片；这条航线你飞过的每一次 | 自己算的太阳位置；实测轮廓；Planespotters（按注册号） |
| 城市 | 卫星影像；国家轮廓上标出城市的位置；用过的机场按真实方位画出跑道；从这里飞去哪里，按次数排成长短条 | Apple 地图影像；world-atlas 国界；OurAirports 跑道 |
| 足迹 | 绕地球几圈：一圈圈光绕着地球盘起来；在天上几天：每小时一格，按那一小时窗外的天色上色；最长的一程和飞得最多的航线；机库：飞过的机型按真实长度排在一起；航司标志；去过的国家是各自的轮廓，按第一次到达排；去过的城市是卫星图格子，按去的次数排；住过的地方是城市小图加一条时间带 | 自己的数据；自己算的太阳位置；实测轮廓；world-atlas 国界 |
| 导入 | 选中的截图直接显示成缩略图；核对时每段带航司标志，勾选是一个对勾；保存后这次涉及的城市以卫星图出现 | 用户自己的文件；Apple 地图影像 |
| 搜索 | 还没输入时依次是接下来的一程、最近三次旅程、最常去的城市（卫星图卡片）；输入后按城市、旅程、航班分组，任何一种叫法都能找到（东京、東京、Tokyo、NRT） | 自己的数据 |

**界面**
- 地球铺满全屏，一张底部卡片（三档高度），卡片底部是分区栏：三个分区收在一枚深色胶囊里，选中的一格亮起；搜索是旁边单独一枚圆钮。打开一页后分区栏让开，返回首页再出现。
- 地球是照片：白天是 NASA Blue Marble，夜里是 Black Marble 的城市灯光，太阳在此刻真实的位置，晨昏线是一条暖色的柔边，海面有一点反光，夜里有一条很淡的海岸线免得陆地消失。打开一班飞机时，太阳在 1.6 秒里转到它起飞的那一刻。照片缺失时退回夜色地球。卡片是深色半透明的玻璃，不用系统灰；没有描边、没有框、没有分隔线，层级靠字号、字重、留白和明暗。
- 浮在地球上的控件是图标本身（搜索、导入、账户），不加玻璃圆圈。
- 返回永远是一步：进入一样东西是压一页，左右翻上一个、下一个（翻页、在地球上点同一类东西）是原地换掉这一页，所以翻了十次也只要返回一次。从左边缘右滑在任何一页都是返回，翻页手势让给它。页顶固定一条：左边写明返回到哪里，长按列出整条路径可以一次跳回；右边是 ‹ n / N ›。网页同一规则：上一个、下一个和地图上点同类对象都用 replace，不进浏览器历史。
- 地球不是空的：夜色地球上，全世界近 5,000 个跑道 1,200 米以上的机场是暗暗的暖色灯点（照片地球上由真实的城市灯光代替），跑道越长越亮，像夜里从轨道上看；自己去过的城市按访问次数标名字，远看几个，拉近逐渐变多，互相避让、淡入淡出，当前页的城市总在最前，放不下时换到点的下方或旁边。打开时镜头从远处转进来；总览对准九成飞行所在的那片区域，不为一次远行把整个地球缩小；新账户还没有航班时对准手机所在的地区。转动或缩放离开后，右上角出现一个回到原视角的按钮。
- 颜色有含义：自己的航线一个色调，联动的人一个色调，一起飞是金色；天色用于时间；航班页顶部带一点这家航司标志的颜色。其余都是黑白灰的明暗。
- 字：系统字体（SF Pro + 苹方）。机场代码和时间是最大的字，数字一律等宽；字号只用 11/13/15/17/22/30/44 几档。

**动线**
- 首页 = 年份尺 + 三个分区。旅程分区是这一段的数字、下一程和旅程，点数字进足迹；足迹分区里地球退到能看见整个世界；点旅程进旅程，点航段进航班，点城市名进城市；点地球上的航线进航班，点城市光点进城市。
- 任何一页都能搜索：城市、机场、航司、航班号、年份。
- 一年、一次旅程、一次航班都能分享成一张图：概览年份尺右下角、旅程页和航班页顶栏的分享按钮，先看到整张卡，再点「分享图片」；分享或存下后预览自己关掉。卡片的设计见[设计原则](DESIGN.md#分享卡片)。
- 首页顶部只有一个大数字（这一段的飞行次数），里程（中文写万公里）、在空中的天数和国家收成一行小字，不让四个一样大的数字挤在一行。卡片最低一档只留年份尺和这个数字，地球最大；其余内容随卡片拉起渐显，最低一档不会被圆角切掉半行。中档是首页的主体；拉满是完整列表。
- 弹出页（设置、导入、搜索）和主卡片同一种深色玻璃底，标题左对齐，右上角是一个不带圈的 ×；主操作是一枚浅色胶囊按钮，其他操作是彩色文字。
- 注册、登录是全屏的一页：大标题，下划线式输入框（标签浮在上面，聚焦时变成色调，密码可以显示），每个框下面一行提示或错误，服务器的错误落到对应的框并轻震；键盘弹起时主按钮跟着键盘，切换"登录 / 注册"的链接让位。不让系统生成强密码：没有关联域名，生成的密码到网页上用不了。
- 设置：顶部是名字和"N 次飞行 · 自 YYYY 年"；语言（跟随手机 / 简体 / 繁體 / English，选了立刻整个 App 换语言）；账户（改名字、改密码、导出全部航班为 JSON）；关于（网页版、数据与影像来源、隐私政策、使用条款）；退出登录要确认；删除账户单独一页，写清会删掉多少段航班、输入密码才能删。

## 技术决定

- **SwiftUI，最低 iOS 26**。不用系统的玻璃按钮样式（`.glass`、`.glassProminent`）和默认的灰色弹出页底，卡片、弹出页、按钮都在 `Features/Theme.swift` 里统一定义。
- **地球用 Metal 自己画**：片元着色器里光线求交画出完美球体；陆地用由 world-atlas 10m 生成的距离场贴图，海岸线和国界在任何缩放下都锐利；航线是屏幕空间展开的光带，额外叠加光晕、按地球遮挡淡出、光点动画。不用 MapKit，因为它的地球模式不支持深色样式，线条也不能发光或动画。MapLibre 的地球模式在 iOS 上还只是预发布版。
- **服务器是唯一的事实来源**：`GET /api/app/archive` 一次给出档案、旅程和住所，推断与网页用的是同一份代码，两边说的话一致。App 把最后一次结果存在本机，离线也能看。
- **登录**：App 请求带 `X-Flyprint-Client: ios`，会话是 Bearer token，存在钥匙串，不用 cookie。
- **导入**：沿用服务器的导入接口（同一套识别与去重）。iOS 加分享扩展、照片和文件选择。
- **城市影像**：`MKMapSnapshotter` 的卫星影像（旅程和城市页顶部用带俯角的写实影像），先按名字地理编码到城区中心（离机场 90 公里以内才算数），只缓存城区中心的结果。快照多画 48 点边距再裁掉，所以图上没有 Apple 地图标志，页面底部用文字署名。现在只给自己和一两个朋友装着用（2026-11-20 决定），就保持这样。**公开分发前要改**：Apple 地图的条款不允许移除它的标志和法律说明，上架或 TestFlight 公测前要么保留标志（去掉 `Visuals.swift` 里的边距裁切），要么换一个允许商用、只需文字署名的影像来源。
- **国家用轮廓，不用国旗**：国旗 emoji 在国行设备上会隐藏台湾旗帜，模拟器（iOS 26.3 运行在 macOS 15 上）也完全渲染不了 emoji；轮廓还能标出城市的位置。轮廓来自 world-atlas 50m，小于 3 万平方公里的地方（香港、澳门、新加坡、马耳他）换成 10m，以国家中心做等积方位投影；远离本土的领地不画，主体以外只留够大的岛（克里特留着，马德拉不让葡萄牙缩成一条），和主体差不多大的部分无论多远都算（马来西亚的两半）；两个要素共用一个代码时取大的（澳大利亚和阿什莫尔群岛都是 036）。城市在被略去的领地上（冲绳、加那利）就不画点。马尔代夫、巴哈马这类散开的群岛在自己的方框里只占几个点，改画成地图集里的定位图：一圈海，附近的海岸淡淡画出，岛亮起，外面一个圆环。网页用同一份文件（`public/countries.json`）。
- **地球照片**：Blue Marble（2004 年 12 月，8192×4096，sRGB）和 Black Marble 2016（4096×2048，灰度、线性）压成 ASTC 4×4 的 KTX（`Resources/earth-day.ktx` 44.7 MB、`earth-night.ktx` 11.2 MB），由 `scripts/build-ios-earth.sh` 从原图生成，不进仓库。夜图里冰原的底色会被读成灯光，所以亮度 0.21 以下切掉。色调映射是 `1 − e^(−x)` 再做 gamma，高光不削平。
- **天气**：App 和网页都只问自己的服务器（`GET /api/weather?at=MUC:2024-10-11,…`，一次最多 64 个机场日），服务器再问 Open-Meteo：7 天前的日子用再分析档案，算是定了，永久缓存；最近和未来 14 天用预报，按远近 3 到 12 小时重取。时间是机场当地时间：按 UTC 取前后各多一天的小时，再用机场的时区换成当地日期和钟点。不能让 Open-Meteo 换时区，它给整段回答一个固定的偏移，是查询当时的那个，冬天查的夏天日子会差一小时，而定了的日子永不重取。夏令时开始那天缺的一小时用前一小时补，结束那天重复的一小时取第一个；一天的最高、最低温、降水和最坏的天气都由这 24 小时算出。一天的代表天气取 8 点到 19 点的小时，最坏的那一小时会把一场傍晚阵雨的晴天说成雨天。缓存在数据目录里单独的 `weather.sqlite`。上游有三道限额：全站每天 3000 次，每个地址每小时 60 次，一次请求最多 8 次（其余留给下一次请求），同样的请求正在进行时合用一个；有缺的回答不缓存（`no-store`），全部是已定日子的回答缓存一周。
- **分享卡片**：`Features/Cards.swift` 用 SwiftUI 排版，`ImageRenderer` 按 4 倍输出 JPEG；地球静帧由 `Globe/GlobePrinter.swift` 用同一套 Metal 着色器离屏画出，地面在静帧里稍稍柔化（`soften`），海岸线留一层底，免得近景成了锯齿。网页 `app/components/cards/` 是同一套相机、取景和点位的移植。
- **日出日落**：`Model/Sky.swift` 是网页 `app/lib/daylight.ts` 的移植，单元测试用网页算出的参考值逐项对照。

## 航班数据：不付费能拿到什么（2026-11-21 调研）

| 想要的 | 免费来源 | 能做到 | 做不到 |
|---|---|---|---|
| 天气 | Open-Meteo（免费、不要 key，非商用，CC BY 4.0） | 已接：过去的再分析、未来两周的预报 | 无 |
| 飞机照片、机型 | Planespotters（已接）；adsbdb（按注册号或 ICAO 地址查机型、运营人，按呼号查航线） | 有注册号就有照片和机型 | 没有注册号时，不知道那天是哪一架 |
| 实际起降时刻、航迹 | adsb.fi 开放接口（实时位置，每秒 1 次，非商用） | 只能"从现在起"录：未来的航班在飞时按呼号记下航迹和真实起降 | 历史回补：免费的只有 adsb.lol 的全球日档（每天约 3.6 GB），量太大；FlightAware、Flightradar24 禁止抓取，接口收费 |
| 中国境内 | 无 | 无 | ADS-B 接收站在中国很少，国内航段几乎录不到 |
| 航班计划、延误 | AeroDataBox（RapidAPI 有免费额度）、OpenSky（研究用历史数据） | 需要注册账户 | 未经同意不注册 |

结论：历史不能免费补齐。能做的是给接下来的航班开一个录航迹的任务（adsb.fi），这需要服务器常驻一个任务，是否做由产品决定。

## 开发

工程由 XcodeGen 从 `ios/project.yml` 生成，`Flyprint.xcodeproj` 和 `Info.plist` 不进仓库。本机的 `xcode-select` 指向命令行工具，所以每条命令前带上 Xcode 的路径：

```sh
cd ios && xcodegen generate
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
xcodebuild -project Flyprint.xcodeproj -scheme Flyprint -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

资源由网页这边的脚本生成，改了来源就重新跑：

| 文件 | 脚本 | 来源 |
|---|---|---|
| `Resources/globe-ground.bin` `.json` | `node scripts/build-ios-globe.mjs` | world-atlas 10m 陆地与国界 → 距离场 |
| `Resources/aircraft.json` | `node scripts/build-ios-aircraft.mjs` | `app/lib/aircraft` 的实测侧视图 |
| `Resources/Assets.xcassets/AppIcon…` | `node scripts/build-icons.mjs` | 与网页同一枚图标 |
| `Resources/countries.json`（网页同一份在 `public/countries.json`） | `node scripts/build-ios-countries.mjs` | world-atlas 50m 国界，小地方用 10m，群岛加 50m 陆地做定位图 |
| `Resources/earth-day.ktx` `earth-night.ktx`（不进仓库） | `scripts/build-ios-earth.sh <blue-marble.jpg> <black-marble.jpg>` | NASA Blue Marble 与 Black Marble 原图 → ASTC 4×4 |
| `Resources/runways.json` | 复制 `app/lib/server/runways.json` | OurAirports 跑道 |
| `Resources/sample.json` | 本地服务器的 `GET /api/app/archive`（未登录） | 示例旅客 |
| 航司标志 | 直接引用 `public/airlines` | 与网页同一套 |

测试：`FlyprintTests` 是几何、数据、日出日落（与网页对照）和国家轮廓的单元测试，用 `Store(restoring: false)` 读内置示例，不受模拟器里登录状态影响；`FlyprintUITests/FlowTests` 走一遍新用户的第一次使用（欢迎页 → 注册 → 自动打开导入 → 粘贴表格 → 核对 → 保存 → 地球 → 设置里切到英文再切回 → 退出 → 登录 → 删除账户），每次自己注册一个一次性账户，需要一台空数据目录的本地服务器，地址通过 `TEST_RUNNER_FP_ORIGIN` 传入；`NavigationTests` 检查边缘右滑总是返回、左右翻页不算一步、转开地球后能一键回到原视角，不需要服务器；`TourTests` 只在设了 `TEST_RUNNER_FP_TOUR=1` 时运行，把每个页面在静止、滚动中、滚到底各截一张（`TEST_RUNNER_FP_SHOTS` 指定目录，`TEST_RUNNER_FP_LANG` 指定语言），账户那一半还会注册、导入、手动添加一段、修改、删除，用来逐张看排版。Debug 构建认这些启动参数，方便截图：`-fp.origin`（服务器地址）、`-fp.reset YES`（清掉登录）、`-fp.year 2019`、`-fp.detent peek|large`、`-fp.tab trips|flights|footprint`、`-fp.route trip#3|flight#next|flight#5|place#TYO|records`（records 即足迹分区）、`-fp.sheet welcome|signin|signup|account|import|search`、`-fp.beat 0|1|2`（欢迎页第几屏）、`-fp.lang.reset YES`（语言回到跟随手机）、`-fp.scroll 0.5`（打开后滚到页面的这个位置）。
