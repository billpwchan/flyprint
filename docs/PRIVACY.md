# 隐私模型

飞行档案能够揭示常驻城市、旅行习惯与活动时间。航迹把代码和个人输入分开，但不会自动替你配置访问权限。

## 数据放在哪里

| 内容 | 位置与处理 | 仍需注意 |
| --- | --- | --- |
| 账户、会话、航班、导入记录、联动与邀请链接（只存散列） | 服务端数据目录里的 SQLite（`FLYPRINT_DATA_DIR`），Git 忽略，不进镜像 | 备份同样需要保护；拿到数据目录就拿到全部航班 |
| 密码 | scrypt 加盐散列 | 弱密码仍可被离线猜测；首次分配的临时密码要尽快修改 |
| 会话 | 随机令牌，数据库只存其 SHA-256；Cookie 为 HttpOnly、SameSite=Lax，HTTPS 下 Secure | 删除账户或改密码会结束其他会话 |
| 试用账户 | 访客第一次导入或手动添加航班时建立：没有邮箱和密码（邮箱栏是 `<id>@guest.invalid` 占位），会话 7 天；每个网络每小时最多 10 个；不能打开公开主页或联动 | 注册时同一个账户补上邮箱和密码；登录已有账户（或重设它的密码）时航班并入（已有的不重复），试用账户连同它的导入记录删除，并入的航班不能再按导入撤销；建立 7 天后未保留的连同航班、导入一起删除（每小时清理一次），结束试用立即删除 |
| 上传的原始文件 | 只在内存中读取，读完即丢弃，不写盘 | 读取结果（航班、座位、舱位、乘机人姓名）留在待核对的草稿里，放弃导入后草稿也删除 |
| 截图、PDF、陌生格式的内容 | 发送给 Anthropic 的 Claude 识别 | 适用 Anthropic 的数据政策；页面在上传前写明了这一点。Flighty 等导出、表格、登机牌、日历和粘贴的条码在服务端解析；其中本站还没有三语名字的机场和航司，只把机场代码（连同内置机场表里的英文城市、机场与国家名）和航司代码交给 Claude 取名，不带日期、航班号或账户 |
| 飞机照片 | 航班页与机队页按注册号由浏览器直接向 Planespotters 的公开接口请求，图片从其服务器加载，服务端不转发也不保存 | Planespotters 会看到访问者的 IP 与所查的注册号；注册号是公开信息，但查询时间与航班页的访问相对应 |
| 天气 | 航班页和旅程页的天气由服务端向 Open-Meteo 查询，只发出机场的经纬度、时区和日期；结果存在数据目录里单独的 `weather.sqlite`，不关联账户 | Open-Meteo 看到的是服务器的 IP；同一时间的查询组合可能对应某次航班页的访问，但不带任何身份 |
| 城市卫星图 | 服务端按城市名向 Open-Meteo 的地名库查城市中心，再向 EOX 取 Sentinel-2 cloudless 2024 的瓦片拼成一张图；每座城市只取一次，图存在数据目录的 `imagery/`，城市中心存在 `imagery.sqlite`，都不关联账户 | EOX 与 Open-Meteo 看到的是服务器的 IP 和城市；某座城市第一次被拼图的时间可能对应某个读者第一次打开它，但不带任何身份。影像以 CC BY-NC-SA 4.0 授权，页面底部写明出处 |
| 联动 | 双方同意后才有同飞页；默认只显示两人都记了的航班，双方都选择“让对方看到全部航线”才叠加各自的其他航线；对方的座位、舱位与机型从不显示 | 任一方可以随时解除，或收回“全部航线” |
| 公开主页 | 默认关闭；打开后 `/s/<随机链接名>` 只给出落地满 3 天的航线、由这些航线连成的往返旅程与城市（配卫星图；搬家、回家的航班和还没回来的旅程不单独列出，常住地也不在城市里）、当地起降时刻与统计，不含座位、舱位、注册号、同飞的人和还没飞的行程；预览图按同样的数据现画 | 链接名不可猜但可被转发；航线本身能透露常驻城市与出行习惯。停止公开后旧链接立即失效，已被聊天软件缓存的预览图可能还会显示一段时间 |
| 来源统计 | 打开带 `?ref=` 的链接时，页面把来源名报给 `/api/arrive`；浏览器里留一个 30 天的 `flyprint_ref` Cookie（HttpOnly），开始试用和注册时按它给该来源加一；数据库只有按天、按来源的访问数、试用数与注册数（`arrivals` 表） | 不存 IP，也不和账户关联；每个 IP 每小时最多计 30 次，每天超过 200 个来源名后新的都记作 other |
| 找回密码 | 只在配置了邮件服务时出现；令牌只存散列，1 小时有效、只能用一次 | 邮件经过 Resend，邮箱地址与邮件内容由其处理 |
| 每日备份 | 数据目录 `backups/` 里保留 7 天的数据库副本 | 删除账户后，备份里的旧副本最迟 7 天后轮换消失；副本与数据库同卷，同样需要保护 |
| `app/data/flights.example.json` | 可提交的合成档案，未登录访客看到的就是它 | 演示组合不代表真实航班或实际执飞 |
| `data/` | Git 忽略，公开导出排除 | 本地数据库和私有档案都在这里 |
| `.env`、`.env.local`、密钥文件 | Git 忽略，公开导出排除 | `.gitignore` 无法隐藏已追踪的文件 |
| `dist/` 与 Docker 镜像 | 只含合成示例 | 仍不要当作源码包发布 |
| 截图、年度 PNG、历史提交 | 需要单独审查 | 普通文本指纹扫描无法证明它们安全 |

个人页面只把当前读者自己的航班交给浏览器。同飞页只对已联动的两个人打开，内容按上面的共享范围裁剪；没有联动的账户之间看不到彼此。航班页不展示档案的采集来源。

## 工程层面的保护

- 构建只包含合成示例；测试各自使用临时的空数据库，不调用模型。
- 写操作拒绝跨站请求；登录与注册有失败次数限制。
- 档案校验的错误只说明字段与行号，不输出私人记录与源文件路径。
- 隐私检查覆盖 Git 追踪与未忽略的未追踪文件；已删除旧文件不视作当前发布内容。
- 公开导出排除环境文件、原始表格、证书、主机配置、历史运维记录、缓存和私有输入，再次扫描导出目录。
- 导出拒绝已存在目标、项目内部或父级目标，以及可能越界的符号链接。

```bash
npm run privacy:check
npm run export:public -- ../flyprint-public
```

检查会发现常见私钥、令牌、本机路径和已知私有来源指纹，并报告文件名，不打印匹配内容。它是启发式检查，不是完整秘密检测器；当前示例检查也不能证明你后来手工替换的内容没有私人信息。

## 历史提交

当前工作仓库的旧版本曾追踪飞行数据。公开导出不复制 `.git`，适合在新目录人工审查后创建全新历史。切勿把原仓库直接推到公开远端并假定删掉文件就足够。详细流程见[开源发布](RELEASING.md)。

若真实数据或凭证已公开，依照[安全政策](../SECURITY.md)限制暴露、撤销凭证并协调历史清理。
